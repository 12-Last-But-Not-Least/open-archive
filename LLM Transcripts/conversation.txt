Assistant — 2026-11-17T01:26:16.431Z

Yes—it all runs in **GitHub Actions**. No separate bot service or server.

For your repo, I’d use two workflows:

**1. The Playwright workflow we added**
Runs the app, takes screenshots, and uploads them as workflow artifacts.

**2. A “Post visual preview” workflow**
Starts automatically when Playwright finishes, using GitHub’s [`workflow_run` trigger](https://docs.github.com/en/actions/reference/workflows-and-actions/events-that-trigger-workflows#workflow_run). It runs a small Node script that:

- **Calls the LLM:** sends the PR diff and screenshot catalog over an HTTPS API request. The API key comes from a GitHub repository secret. The response contains screenshot names.
- **Stores the chosen PNGs:** downloads the artifacts and saves the selected images to a dedicated `pr-preview-images` branch in your public repo.
- **Posts the comment:** calls GitHub’s [comment API](https://docs.github.com/en/rest/issues/comments) using the workflow’s built-in `GITHUB_TOKEN`. The author appears as **`github-actions[bot]`**—that’s the “bot.”

The comment contains ordinary Markdown:

```markdown
### Invitation popup — desktop
![Before](URL-to-before.png)
![After](URL-to-after.png)
```

So “attach” means **put the PNG somewhere accessible, then embed its URL in the comment**. A workflow artifact alone isn’t an inline image.

The second workflow keeps the LLM key and comment-writing permission separate from running PR code. You’d only supply the LLM API key; GitHub supplies the bot identity and GitHub token.
